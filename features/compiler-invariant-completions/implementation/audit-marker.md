## Goal

Land the `InternalStateEnum` opt-out vehicle marker trait at a new top-level crate module `compiler/src/audit_markers.rs` (rustdoc body binds the opt-out attestation semantic per decisions.md 2026-05-14), so every downstream chunk landing an internal-state pub enum reachable from `ModIR` has the cross-chunk symbol available to write `impl InternalStateEnum for X {}` at the enum's declaration site.

## Brief link

- **Goal advanced (foundational only):** "Every IR shape variant is corpus-evidenced or explicitly an escape-hatch." This chunk lands the cross-chunk symbol every internal-state pub enum reachable from `ModIR` will attach to via `impl InternalStateEnum for X {}`. The Goal's verifier — "the audit fails closed when an in-scope shipping IR shape is neither corpus-evidenced nor present in the registry" — is delivered by `audit-harness`, not this chunk; the symbol delivered here is `audit-harness`'s mechanical prerequisite. - **Non-goal honored — the no-new-author-ergonomics Non-goal:** "No new author-ergonomics surface, with bounded carve-outs." The new `compiler/src/audit_markers.rs` module is not an authoring module — the marker trait carries no methods, no associated types, no construction helpers, no `::new`; it is a pure opt-out attestation symbol consumed by downstream chunks' `impl` statements plus by `audit-harness`'s `syn`-walker, never by mod authors. - **`pub` visibility on trait + module, with mandatory crate-root re-export** (per decisions.md 2026-05-13 literal `pub` + decisions.md 2026-05-15 re-export binding): the chunk MUST add `pub use audit_markers::InternalStateEnum;` to `compiler/src/lib.rs` immediately after the existing `pub use ir::Source;` line, matching the established crate-root re-export pattern for sibling pub IR-adjacent types (`pub use ir::Source;`, `pub use finding::{Finding, Severity};` in `compiler/src/lib.rs`). The re-export is load-bearing for consumer-import-path stability: a future refactor moving the trait to a different sub-module path breaks every consumer using the longer-form path; consumers using `textmod_compiler::InternalStateEnum` remain stable.
- **Trait identifier `InternalStateEnum` is the syn-walker's match key via the trait path's last segment (cross-chunk contract).** `audit-harness`'s `syn` Layer-1 walker matches `syn::ItemImpl.trait_` whose path's last segment (`syn::Path::segments.last()`) equals `InternalStateEnum`; both bare (`impl InternalStateEnum for X {}`) and path-qualified (`impl crate::audit_markers::InternalStateEnum for X {}`, `impl textmod_compiler::InternalStateEnum for X {}`) impl forms resolve under the same match key because both end in the same final segment. The path-segment match mechanism (vs naive text regex over the impl line) is bound in decisions.md 2026-05-15 point 1. A rename of the trait without coordinated update of `audit-harness`'s walker pattern AND every impl site silently breaks discovery; the path-segment match mechanism does NOT mitigate trait-rename risk, only path-qualifier-style variation at impl sites. Renaming the trait is forbidden by the engineering plan's Contract edges row (`audit-marker → all chunks landing new internal-state pub IR enums`); if a future need arises, the rename ships as a CLAUDE.md retirement-protocol bundle (rename comment + permanent guard test + coordinated `audit-harness` walker update) in a single chunk.
- **Rustdoc body binds opt-out semantic; names per-impl rustdoc obligation with mandatory outer-`///` placement:** the trait's `///` doc-comment (i) names what an `impl` attests (NOT input-bytes-determined; exempt from corpus-evidence walk), (ii) names the default for in-scope reachable pub enums (must be corpus-evidenced, registry-listed, or brief-deferred), (iii) cites the binding entries `decisions.md` 2026-05-14 "Vehicle marker semantics" + `decisions.md` 2026-05-15 (mechanism refinement), (iv) names the per-impl rustdoc obligation as the **only** check on attestation correctness — `audit-harness`'s `syn`-walker mechanically enforces *presence* of at least one **outer** `#[doc = ...]` attribute on every `impl InternalStateEnum for X {}` by filtering `ItemImpl.attrs` to entries where `Attribute.style == AttrStyle::Outer AND` the attribute path resolves to `doc` (per decisions.md 2026-05-15 point 2), but the doc-comment's *content* is human-review-only; an empty or vacuous comment ships a silent bypass. The outer-doc-comment placement (`///` immediately above the `impl` line) is mandatory: inner `//!` doc-comments inside the impl block attach with `AttrStyle::Inner` and do NOT satisfy the attestation; `///` doc-comments placed between the impl block's `{` and `}` either are a parse error (empty impl body has no next item to attach to) or attach to the next nested item (none here). The trait-level rustdoc is the canonical reference text the implementer reads when writing `impl InternalStateEnum for X {}`.
