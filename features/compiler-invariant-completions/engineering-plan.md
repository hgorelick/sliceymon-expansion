## Architecture summary

The compiler closes nine residual invariants across the typed IR, the cross-IR rule layer, the build-time harvester, the derived-structural regenerator dispatch, and the authority-doc vocabulary. The technical core is the typed `ItempoolItem::NonSummon(NonSummonEntry)` sum that lands in `nonsummon-typed-schema` — every chunk that downstream-affects `ItempoolItem` shape sequences after it. The typed-summon classifier (`typed-summon-extractor`) consumes the typed `NonSummonEntry` to route non-matches; the `single-finding-name-collision` chunk dispatches on the typed `Finding.buckets: Vec<&'static str>` + `Finding.includes_boss: bool` fields the typed-summon-extractor chunk introduces, replacing the today's `Finding.message`-substring scans inside the two collision-detection rules.

Five chunks ship independently of that three-phase chain: `ir-shape-evidence-audit` lands the variant-evidence audit harness + the `closed_escape_hatch_registry` plus the vehicle-marker definition every chunk introducing a pub IR enum attaches to; `harvester-byte-determinism` extracts the harvester pure core into `compiler/src/harvester/` (reachable from library code without `std::fs` per SPEC §3.4, with `compiler/build.rs` retained as the I/O shell); `complete-regenerators` lands `generate_pool_replacement` and rewrites `generate_char_selection`'s body inside the same dispatch function in `compiler/src/ir/merge.rs::regenerate_derived_kinds`; `authorable-new-constructors` adds `::new(identity)` to four authorable IR types without `Default` derive; `authority-doc-vocab-alignment` strips retired IR-identifier names from SPEC §10 glossary heading while preserving the player-facing role description (per decisions.md 2026-05-12) and installs a permanent `compiler/tests/` guard against the retired tokens in authority docs; `summon-name-rename` performs the atomic `target_name` → `summon_name` rename across every callsite.

Cross-chunk contracts the engineering plan introduces — `compiler/src/harvester/` module, `harvest_face_ids` + `harvest_sprites` (existing build-script entry points at `compiler/build.rs` retained at their current names; the chunk extracts the pure core in place), `closed_escape_hatch_registry` (two entries: `FaceIdValue::Unknown` enum variant + unknown-sprite escape hatch), the opt-out vehicle marker for compiler-internal-state IR enums (per the inverted-semantics binding in Decisions closure), the two introduced `check_replica_item_in_context` and `check_monster_in_context` per-entity context-checks parallel to `check_hero_in_context` and `check_boss_in_context` (uniform four-CRUD pattern; `find_name_category` retires fully), `compiler::authoring::sprite::SPRITE_REGISTRY` access-path stability, `NonSummonEntry` and `SummonClassification` (declared in `compiler/src/ir/` and `compiler/src/extractor/` respectively per `nonsummon-typed-schema`'s IR schema block), `Finding.buckets`, `Finding.includes_boss`, `DerivedKind` (4-variant sub-enum mirroring `is_derived()`'s allowed-set, declared in `compiler/src/ir/mod.rs` by `complete-regenerators`), `summon_name` — are the durable surface every chunk in this feature consumes against.

## Invariants

### Single finding per cross-IR defect at every emission surface

The two cross-IR collision-detection rules (V020 cross-category-names, X003 owner-map-bucket-collision) have disjoint-by-construction domains across every xref.rs emission surface (`check_cross_category_names` and every branch of all four per-entity context-checks: `check_hero_in_context`, the newly-introduced `check_replica_item_in_context`, the newly-introduced `check_monster_in_context`, and `check_boss_in_context`) AND at the lib's single-item CRUD surface (every one of `ModIR::add_hero` / `add_replica_item` / `add_monster` / `add_boss` invokes its matching context-check as the sole pre-add validation gate; the private `find_name_category` helper retires fully). A name collision across `{hero, replica_item, monster}` produces exactly one X003 finding regardless of how many categories share it; a boss-involving collision or intra-bucket duplicate produces exactly one V020 finding; a hero color collision produces exactly one V019 finding (emitted only from `check_hero_in_context`, the standalone color-uniqueness check in `ModIR::add_hero` having retired). The narrowing predicate ("colliding category set is subset of `{hero, replica_item, monster}` with cardinality ≥2") is factored into a shared helper invoked from every site. Enforced by `single-finding-name-collision`.

### Corpus-evidenced IR shapes via transitive walk

Every pub `enum` whose variant choice depends on input mod bytes, reachable transitively from `ModIR` via field traversal, is either corpus-evidenced (the audit walks `working-mods/{sliceymon,pansaer,punpuns,community}.txt` and finds an instance) or present in the closed escape-hatch registry (`FaceIdValue::Unknown` + unknown-sprite). New IR-reachable input-bytes-determined enums are audit-covered automatically; per-enum opt-in is forbidden. The audit fails closed when an in-scope shipping shape passes neither test. **Audit Layer-2 prerequisite:** every type reachable from `ModIR` via field traversal derives `schemars::JsonSchema` — the audit's reachability walk uses `schemars::schema_for!(ModIR)`'s `definitions` map to enumerate reachable enums, so a reachable type without the derive falls out of the walk and silently misses coverage; `ir-shape-evidence-audit`'s chunk plan installs a permanent guard against `ModIR`-reachable types lacking the derive (mechanism — guard test, audit refusal, or other — chunk-internal). Enforced by `ir-shape-evidence-audit`.

### Byte-deterministic generated source

`face_id_generated.rs` and `sprite_registry_generated.rs` (the two harvester-emitted files) are byte-identical across repeated harvester invocations against the same corpus. The harvester pure core in `compiler/src/harvester/` is library-importable without `std::fs`; the lexical denylist + `compiler/build.rs` allowlist forbid wall-clock, environment, hash-map iteration, OnceLock, and other process-distinguishable inputs. Enforced by `harvester-byte-determinism`.

### No raw-passthrough IR payloads

No IR variant carries a `String` / `Vec<u8>` / `serde_json::Value` blob holding bytes the parser refused to type. The current `ItempoolItem::NonSummon { name: String, tier: Option<i8>, content: String }` variant declaration in `compiler/src/ir/mod.rs` retypes to `NonSummon(NonSummonEntry)` — a fully typed recursive sum with a permissive-extract `Unclassified` variant whose paired `Finding` populates `field_path` + `suggestion` per SPEC §5 (not a raw escape). The retype retires today's stub-sentinel protocol atomically — the empty-`name` + `None`-`tier` + non-empty-`content` combination produced by the stub body inside `extract_from_itempool` in `compiler/src/extractor/replica_item_parser.rs` doubles as a sentinel that the `emit_itempool` function's `NonSummon`-arm sentinel-detection branch in `compiler/src/builder/replica_item_emitter.rs` detects to skip the `.n.<name>.tier.<n>` prefix synthesis it would otherwise emit; that sentinel-detection branch retires in the same chunk. Enforced by `nonsummon-typed-schema`; extension to the typed payload variants is automatic under the corpus-evidenced IR shapes invariant above.

### Derived-structural dispatch completeness

`complete-regenerators` introduces a new `pub enum DerivedKind { Selector, HeroPoolBase, PoolReplacement, ItemPool }` declared in `compiler/src/ir/mod.rs` alongside `StructuralType` — a 4-variant sub-enum that becomes the **single source-of-truth** for which `StructuralType` variants are derived. `DerivedKind` carries a `TryFrom<StructuralType>` impl that succeeds for exactly those four variants and fails (`Err`) for the other 14 of `StructuralType`'s 18 variants, plus an inverse `From<DerivedKind> for StructuralType` for symmetry. `StructuralModifier::is_derived()` is rewritten to delegate to this `TryFrom` — its body becomes `self.derived && DerivedKind::try_from(&self.modifier_type).is_ok()`, retiring the existing 4-variant `matches!` literal so the predicate consults `DerivedKind`'s variant set rather than its own parallel encoding (per decisions.md 2026-05-13 "`DerivedKind` is single source-of-truth; `is_derived()` delegates"). The dispatch in `compiler/src/ir/merge.rs::regenerate_derived_kinds` splits into a thin outer function (filters `StructuralType` → `DerivedKind` via the `TryFrom` impl; the outer arm on `Err` is structurally unreachable since the `kinds` argument is built upstream by `compiler/src/ir/merge.rs::collect_stripped_kinds`, which filters by `StructuralModifier::is_derived()` — and `is_derived()` returns true only when `DerivedKind::try_from` succeeds) and an inner function exhaustive over `DerivedKind`'s four variants — Rust's compiler-enforced exhaustiveness check on `DerivedKind` is the property's load-bearing enforcer. The wildcard `_ => {}` arm inside `regenerate_derived_kinds` retires; flipping a fifth `StructuralType` variant to derived requires only one step — extending `DerivedKind` with a corresponding variant — which then forces the inner exhaustive-match arm at compile time AND auto-flips `is_derived()`'s output for the new variant (because `is_derived()` consults `DerivedKind::try_from`). Enforced by `complete-regenerators` (DerivedKind + TryFrom + inverse From + outer/inner split + `is_derived()` delegation rewrite + a guard test in `compiler/tests/` that constructs a `StructuralModifier` for every variant `is_derived()` returns true on and asserts each regenerates without panic or sink, complementing the compile-time variant-coverage check with per-arm correctness verification).

## Build determinism

`compiler/build.rs` reaches the harvester pure core at `compiler/src/harvester/` via `#[path = "src/harvester/mod.rs"]` declaration. The pure core returns `Vec<(String, String)>` pairs for the face-ID and sprite registries; `compiler/build.rs` glue assembles `phf::Map` via `phf_codegen::Map::build()` and writes `face_id_generated.rs` + `sprite_registry_generated.rs`. The pure core takes `&[(name, contents)]` slices in memory (no `Path` arguments, no `std::fs`). Two harvester invocations against the same corpus produce byte-identical output; the `harvester-byte-determinism` chunk's `audit_harvester_determinism.rs` integration test exercises this property in-process. The build-time SHA-256 ledger captured during the chunk's pre-vs-post refactor pass is the chunk's PR-attached test evidence.

## Rollout plan

The compiler ships as a single Rust crate consumed by `compiler/src/main.rs` (CLI) and downstream features. No flag system, no migration window, no telemetry. Each chunk lands as one PR; each PR re-runs the four-mod round-trip baseline (`cargo run --example roundtrip_diag`) and `cargo test`. Failures block the merge. The four corpus mods (`working-mods/{sliceymon,pansaer,punpuns,community}.txt`) are the rollback authority — any chunk whose merge degrades round-trip equality on any of the four reverts.
