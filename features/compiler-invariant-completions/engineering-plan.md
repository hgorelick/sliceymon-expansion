## Architecture summary

The compiler closes nine residual invariants across the typed IR, the cross-IR rule layer, the build-time harvester, the derived-structural regenerator dispatch, and the authority-doc vocabulary. Per `decisions.md` 2026-05-14 decomposition + 2026-05-19 sibling-chunk addition, the work ships as fifteen chunks: three dependency chains (audit, harvester, typed-IR/dedupe), the `complete-regenerators` → `poolreplacement-typed-payload` pair, and three standalone independents.

The typed-IR / dedupe chain (`nonsummon-typed-ir` → `nonsummon-typed-authoring` and `nonsummon-typed-ir` → `typed-summon-extractor` → `xref-context-check-introduction` → `xref-narrowing-and-rename`) is the technical core. `nonsummon-typed-ir` lands the SPEC §3.7 atomic retype of `ItempoolItem::NonSummon { name, tier, content }` to `NonSummon(NonSummonEntry)`; `nonsummon-typed-authoring` adds the strict-validation authoring builders (T34 + T30.16c); `typed-summon-extractor` consumes the typed `NonSummonEntry` to route non-matches and lands `Finding.buckets` + `Finding.includes_boss`; the `xref-context-check-introduction` + `xref-narrowing-and-rename` pair dispatches the dedupe predicate on the typed `Finding` fields.

The audit chain (`audit-marker` → `audit-marker-retrofit` → `audit-harness`) lands the variant-evidence invariant. `audit-marker` declares the `InternalStateEnum` opt-out marker trait at `compiler/src/audit_markers.rs` per `decisions.md` 2026-05-14 + 2026-05-13. `audit-marker-retrofit` applies the marker to the three existing Layer-2-reachable internal-state pub enums (`Source`, `StructuralType`, `Severity`) per the partition documented in `decisions.md` 2026-05-13 widening entry. `audit-harness` ships the Layer-1 `syn` walk + Layer-2 `schemars::schema_for!(ModIR)` walk + closed escape-hatch registry + the audit CI test, with the contingent variant-deletion + retirement-protocol bundle landing in the same chunk if first run flags unevidenced shapes.

The harvester chain (`harvester-pure-core` → `harvester-determinism-audit`) lands the byte-determinism invariant. `harvester-pure-core` extracts the pure core into `compiler/src/harvester/` (library-reachable without `std::fs` per SPEC §3.4, with `compiler/build.rs` retained as the I/O shell). `harvester-determinism-audit` lands the in-process double-invocation CI test + lexical denylist + pre-vs-post SHA-256 ledger.

The `complete-regenerators` → `poolreplacement-typed-payload` pair (Foundation → Second wave per decisions.md 2026-05-19) lands the derived-structural completion. `complete-regenerators` introduces `DerivedKind` in `compiler/src/ir/mod.rs`, rewrites `compiler/src/ir/merge.rs::regenerate_derived_kinds` into an outer/inner dispatch split, retires the `_ => {}` wildcard sink, lands the canonical-shape `generate_pool_replacement(heroes: &[Hero])` for the `derived: true` synthesized case (structurally minimal `((heropool.<list>))` form), and rewrites `generate_char_selection`'s body to the canonical SeqPhase form per `reference/textmod_guide.md`. `poolreplacement-typed-payload` widens `StructuralContent::PoolReplacement` to a typed payload (`hidden: bool`, `doc: Option<String>`, `entries: Vec<PoolReplacementEntry>`), widens `parse_poolreplacement` to populate it, widens the emitter arm to reconstruct from it, widens `generate_pool_replacement` to read from the typed fields (atomically replacing the Foundation-wave canonical-shape body), and flips the extractor's `make_structural` `derived: false → true` initialization for PoolReplacement specifically per decisions.md 2026-05-19 — together delivering the brief's PoolReplacement four-mod byte-match verifier. The atomic-replacement of `generate_pool_replacement`'s body across the pair is bound by SPEC §3.7 (the Foundation chunk's source-vs-IR divergence tests against synthesized heroes establish "regenerator reads from content", the property the typed-payload chunk preserves while widening to corpus byte-match).

Three chunks ship independent of these chains and the pair: `authorable-new-constructors` adds `::new(identity)` to four authorable IR types without `Default` derive; `authority-doc-vocab-alignment` strips retired IR-identifier names from SPEC §10 glossary heading while preserving the player-facing role description (per decisions.md 2026-05-12) and installs a permanent `compiler/tests/` guard against the retired tokens in authority docs; `summon-name-rename` performs the atomic `target_name` → `summon_name` rename across every callsite.

Cross-chunk contracts the engineering plan introduces — `compiler/src/harvester/` module, `harvest_face_ids` + `harvest_sprites` (existing build-script entry points at `compiler/build.rs` retained at their current names; `harvester-pure-core` extracts the pure core in place), `closed_escape_hatch_registry` (two entries: `FaceIdValue::Unknown` enum variant + unknown-sprite escape hatch; landed by `audit-harness`), `InternalStateEnum` opt-out vehicle marker trait at `compiler/src/audit_markers.rs` (landed by `audit-marker`; applied to internal-state enums by `audit-marker-retrofit` and by every chunk introducing a new ModIR-reachable internal-state pub enum), the two introduced `check_replica_item_in_context` and `check_monster_in_context` per-entity context-checks parallel to `check_hero_in_context` and `check_boss_in_context` (uniform four-CRUD pattern; landed by `xref-context-check-introduction`; `find_name_category` retires fully there), `textmod_compiler::authoring::sprite::SPRITE_REGISTRY` access-path stability, `NonSummonEntry` and `SummonClassification` (declared in `compiler/src/ir/` and `compiler/src/extractor/` respectively; landed by `nonsummon-typed-ir`), `Finding.buckets`, `Finding.includes_boss` (landed by `typed-summon-extractor`), `DerivedKind` (4-variant sub-enum mirroring `is_derived()`'s allowed-set, declared in `compiler/src/ir/mod.rs` by `complete-regenerators`), `PoolReplacementEntry` (typed sum modeling bare-hero rows AND inline `(replica.<X>.abilitydata.(...))` rows in PoolReplacement bodies, declared in `compiler/src/ir/mod.rs` by `poolreplacement-typed-payload`; input-bytes-determined per the corpus-evidence Goal, no marker attachment), `summon_name` — are the durable surface every chunk in this feature consumes against.

## Invariants

### Single finding per cross-IR defect at every emission surface

The two cross-IR collision-detection rules (V020 cross-category-names, X003 owner-map-bucket-collision) have disjoint-by-construction domains across every xref.rs emission surface (`check_cross_category_names` and every branch of all four per-entity context-checks: `check_hero_in_context`, the newly-introduced `check_replica_item_in_context`, the newly-introduced `check_monster_in_context`, and `check_boss_in_context`) AND at the lib's single-item CRUD surface (every one of `ModIR::add_hero` / `add_replica_item` / `add_monster` / `add_boss` invokes its matching context-check as the sole pre-add validation gate; the private `find_name_category` helper retires fully). A name collision across `{hero, replica_item, monster}` produces exactly one X003 finding regardless of how many categories share it; a boss-involving collision or intra-bucket duplicate produces exactly one V020 finding; a hero color collision produces exactly one V019 finding (emitted only from `check_hero_in_context`, the standalone color-uniqueness check in `ModIR::add_hero` having retired). The narrowing predicate ("colliding category set is subset of `{hero, replica_item, monster}` with cardinality ≥2") is factored into a shared helper invoked from every site. Enforced by `xref-context-check-introduction` (per-entity context-check introduction + CRUD routing + `find_name_category` retirement) and `xref-narrowing-and-rename` (V020 narrowing predicate + per-target X003 routing + `humanize_bucket` + `"legendary"` retirement); the dedupe Goal's exactly-one-finding property lands when `xref-narrowing-and-rename` merges.

### Corpus-evidenced IR shapes via transitive walk

Every pub `enum` whose variant choice depends on input mod bytes, reachable transitively from `ModIR` via field traversal, is either corpus-evidenced (the audit walks `working-mods/{sliceymon,pansaer,punpuns,community}.txt` and finds an instance) or present in the closed escape-hatch registry (`FaceIdValue::Unknown` + unknown-sprite). New IR-reachable input-bytes-determined enums are audit-covered automatically; per-enum opt-in is forbidden. The audit fails closed when an in-scope shipping shape passes neither test. **Audit Layer-2 prerequisite:** every type reachable from `ModIR` via field traversal derives `schemars::JsonSchema` — the audit's reachability walk uses `schemars::schema_for!(ModIR)`'s `definitions` map to enumerate reachable enums, so a reachable type without the derive falls out of the walk and silently misses coverage; `audit-harness`'s chunk plan installs a permanent guard against `ModIR`-reachable types lacking the derive (mechanism — guard test, audit refusal, or other — chunk-internal). Enforced by the audit chain (`audit-marker` lands the marker trait; `audit-marker-retrofit` applies it to existing Layer-2-reachable internal-state enums; `audit-harness` lands the CI test + first-run retrofit + escape-hatch-registry consultation).

### Byte-deterministic generated source

`face_id_generated.rs` and `sprite_registry_generated.rs` (the two harvester-emitted files) are byte-identical across repeated harvester invocations against the same corpus. The harvester pure core in `compiler/src/harvester/` is library-importable without `std::fs`; the lexical denylist + `compiler/build.rs` allowlist forbid wall-clock, environment, hash-map iteration, OnceLock, and other process-distinguishable inputs. Enforced by `harvester-pure-core` (pure-core extraction + one-time pre-vs-post SHA-256 divergence check per decisions.md 2026-05-14) and `harvester-determinism-audit` (recurring CI in-process double-invocation test + lexical denylist on `compiler/src/harvester/**/*.rs`).

No IR variant carries a `String` / `Vec<u8>` / `serde_json::Value` blob holding bytes the parser refused to type. ### Derived-structural dispatch completeness

`complete-regenerators` introduces a new `pub enum DerivedKind { Selector, HeroPoolBase, PoolReplacement, ItemPool }` declared in `compiler/src/ir/mod.rs` alongside `StructuralType` — a 4-variant sub-enum that becomes the **single source-of-truth** for which `StructuralType` variants are derived. `DerivedKind` carries a `TryFrom<StructuralType>` impl that succeeds for exactly those four variants and fails (`Err`) for the other 14 of `StructuralType`'s 18 variants, plus an inverse `From<DerivedKind> for StructuralType` for symmetry. `StructuralModifier::is_derived()` is rewritten to delegate to this `TryFrom` — its body becomes `self.derived && DerivedKind::try_from(&self.modifier_type).is_ok()`, retiring the existing 4-variant `matches!` literal so the predicate consults `DerivedKind`'s variant set rather than its own parallel encoding (per decisions.md 2026-05-13 "`DerivedKind` is single source-of-truth; `is_derived()` delegates"). The dispatch in `compiler/src/ir/merge.rs::regenerate_derived_kinds` splits into a thin outer function (filters `StructuralType` → `DerivedKind` via the `TryFrom` impl; the outer arm on `Err` is `unreachable!()` since the `kinds` argument is built upstream by `compiler/src/ir/merge.rs::collect_stripped_kinds`, which filters by `StructuralModifier::is_derived()` — and `is_derived()` returns true only when `DerivedKind::try_from` succeeds — so any reached `Err` indicates the `is_derived()`-delegates-to-`DerivedKind::try_from` discipline has been broken and surfaces as a runtime panic at first test invocation rather than as a silent no-op) and an inner function exhaustive over `DerivedKind`'s four variants — Rust's compiler-enforced exhaustiveness check on `DerivedKind` is the property's load-bearing enforcer. The wildcard `_ => {}` arm inside `regenerate_derived_kinds` retires; flipping a fifth `StructuralType` variant to derived requires only one step — extending `DerivedKind` with a corresponding variant — which then forces the inner exhaustive-match arm at compile time AND auto-flips `is_derived()`'s output for the new variant (because `is_derived()` consults `DerivedKind::try_from`). Enforced by `complete-regenerators` (DerivedKind + TryFrom + inverse From + outer/inner split + `is_derived()` delegation rewrite + a guard test in `compiler/tests/` that constructs a `StructuralModifier` for every variant `is_derived()` returns true on and asserts each regenerates without panic or sink, complementing the compile-time variant-coverage check with per-arm correctness verification).

## Build determinism

`compiler/build.rs` reaches the harvester pure core at `compiler/src/harvester/` via `#[path = "src/harvester/mod.rs"]` declaration. The pure core's per-entry return shapes are asymmetric to match the differing per-entry provenance emission shapes of `face_id_generated.rs` and `sprite_registry_generated.rs`: `harvest_face_ids` returns `Vec<(String, String)>` pairs (per-entry block including the `///` doc-comment provenance line in the second element); `harvest_sprites` returns `Vec<(String, String, String)>` triples (sprite name in the first element, `SpriteId` value-expression in the second element, `<mod_name>:<line_no>` provenance suffix in the third element — the third column required because today's `emit_sprite_registry` emits the provenance comment block in a separate position above the phf static). `compiler/build.rs` glue iterates the `harvest_sprites` triples once to emit the provenance comment block and a second time to feed `(name, value_expr)` into `phf_codegen::Map.entry(...)`, then assembles `phf::Map` via `phf_codegen::Map::build()` and writes `face_id_generated.rs` + `sprite_registry_generated.rs`. The pure core takes `&[(name, contents)]` slices in memory (no `Path` arguments, no `std::fs`). Two harvester invocations against the same corpus produce byte-identical output; `harvester-determinism-audit`'s `audit_harvester_determinism.rs` integration test exercises this property in-process. The build-time SHA-256 ledger captured during `harvester-pure-core`'s pre-vs-post refactor pass is `harvester-pure-core`'s PR-attached test evidence (per decisions.md 2026-05-14 "Harvester SHA ledger consolidation").

## Rollout plan

The compiler ships as a single Rust crate consumed by `compiler/src/main.rs` (CLI) and downstream features. No flag system, no migration window, no telemetry. Each chunk lands as one PR; each PR re-runs the four-mod round-trip baseline (`cargo run --example roundtrip_diag`) and `cargo test`. Failures block the merge. The four corpus mods (`working-mods/{sliceymon,pansaer,punpuns,community}.txt`) are the rollback authority — any chunk whose merge degrades round-trip equality on any of the four reverts.
